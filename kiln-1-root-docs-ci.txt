# Kiln

A fast, secure, cross-platform Minecraft Java Edition launcher (Windows, macOS, Linux).
"Kiln" is a working codename: the display name lives in `kiln_core::APP_NAME` and
`src-tauri/tauri.conf.json`.

> Kiln is not affiliated with Mojang or Microsoft. Minecraft is a trademark of Mojang AB.
> A legitimately owned Minecraft account is required for online play.

**Status:** Phase 2 of 8 done (scaffold, settings, SQLite, logging, CI, Microsoft sign-in with OS keychain). Real sign-in needs an approved client ID: see [docs/AUTH.md](docs/AUTH.md). See
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the roadmap.

## Layout

| Path | Purpose |
|---|---|
| `crates/kiln-core` | All launcher logic. No GUI dependency, fully unit-tested. |
| `src-tauri` | Tauri 2 shell: validates IPC input, calls core, maps errors. |
| `ui` | Svelte 5 + TypeScript + Tailwind 4 frontend. |

## Build and test

Requirements: Rust 1.85+, Node 22+. On Linux, Tauri's system libraries
(`libwebkit2gtk-4.1-dev`, `libgtk-3-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`,
`libsoup-3.0-dev`) plus `libdbus-1-dev` for the keychain.

```sh
# Core logic only (no WebView libraries needed)
cargo test

# Whole workspace, as CI runs it
(cd ui && npm ci && npm run build)
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# UI checks
(cd ui && npm run check && npm test)

# Run the desktop app
cargo install tauri-cli --version "^2" --locked
cargo tauri dev
```

`npm run dev` inside `ui/` also works in a plain browser using an in-memory stand-in for
the backend, which is handy for styling work. Set `KILN_LOG=debug` (any `tracing` filter)
to override the log level.

## Data and portable mode

Data lives in the platform data directory under `Kiln`. Create a file or folder named
`kiln-portable` next to the executable to keep everything in `kiln-data/` beside the app.

## Security model (summary)

Full document arrives in Phase 8. What already holds:

- Only the `allow-*` permissions in `src-tauri/capabilities` are granted to the webview;
  there are no `fs`, `shell` or `http` plugins.
- Strict CSP: no inline or remote scripts, no `eval`, fonts and styles from the app only.
- Every log line passes through a redactor that masks tokens, launch credentials,
  e-mail addresses and OS account names before it is written.
- `SafePath` is the only way to turn untrusted relative paths into file operations: it
  rejects `..`, absolute paths, Windows device names and symlink escapes.
- Sign-in tokens: refresh tokens exist only in the OS keychain, access tokens only in memory, and
  none ever reaches the webview or a log.
- All network traffic goes through one client that is HTTPS-only, allowlisted by host and
  never follows redirects.
- Hashes are verified with SHA-1/256/512 before any downloaded file is kept.
- No telemetry.

## Licensing

Kiln is released under **GPL-3.0-only** (see `LICENSE`). Bundled or auto-installed mods
keep their own licenses; Kiln only downloads them from their official source and never
redistributes them itself.

# Microsoft sign-in

## How it works

Kiln uses Microsoft's **device-code flow**: the app shows a short code, the user enters it
on microsoft.com in any browser, and Kiln polls until they finish. There is no embedded
webview, no local redirect server, and Kiln never sees the user's password.

```
Microsoft device code -> MS access + refresh token
  -> Xbox Live user token -> XSTS token (relying party rp://api.minecraftservices.com/)
  -> Minecraft access token -> Minecraft profile (404 means the account doesn't own the game)
```

Where things live:

| Item | Storage |
|---|---|
| Refresh token | OS keychain only (Credential Manager / Keychain / Secret Service), stored as raw bytes |
| Minecraft access token | Memory only, wiped on drop, refreshed ~5 minutes before expiry |
| Device code | Memory only, never sent to the UI |
| Account name, skin hash, flags | SQLite (`accounts` table), no secrets |

No token ever crosses the IPC boundary. The UI receives `Account` and `DeviceCodeInfo`; only the
launch pipeline can ask the backend for a `LaunchSession`.

## Setup you must do before real sign-in works

1. **Azure app registration** (portal.azure.com, App registrations, New registration).
   - Supported account types: personal Microsoft accounts (consumer accounts).
   - Name: must not contain "Mojang", "Minecraft" or similar protected words.
   - Redirect URI: leave empty (device flow doesn't use one).
   - Authentication, Advanced settings: **Allow public client flows = Yes**. Without this Microsoft
     returns `AADSTS70002`.
   - No client secret. Copy the **Application (client) ID**, a GUID.
2. **Ask Mojang to approve the client ID** at <https://aka.ms/mce-reviewappid>. Until then
   `login_with_xbox` answers 403 "Invalid app registration" and Kiln shows
   "Mojang hasn't approved this build's Microsoft app registration". Reviews have been reported as
   weekly; the form is authoritative, not this document.
3. **Give the ID to Kiln**, either:
   - at runtime: `KILN_MS_CLIENT_ID=<guid> cargo tauri dev` (handy while testing), or
   - at build time: set `KILN_MS_CLIENT_ID` in the environment when building releases (it is read
     with `option_env!`). A client ID is public information, not a secret.

Anything that isn't a well-formed GUID is treated as "not configured".

These steps were checked against third-party documentation and a Microsoft Q&A thread, not
Mojang's own pages. Verify against the form before relying on them.

## Errors users can see

| Situation | Message gist |
|---|---|
| No client ID in this build | Sign-in isn't set up in this build |
| Code not used in time | The code expired, start again |
| Declined on Microsoft's page | Sign-in was cancelled |
| XSTS `2148916233` | No Xbox profile yet; sign in at xbox.com once |
| XSTS `2148916235` | Xbox unavailable in the account's region |
| XSTS `2148916236` / `2148916237` | Adult verification needed |
| XSTS `2148916238` | Child account; an adult must add it to a family group |
| Profile 404 | Account doesn't own Minecraft: Java Edition |
| Refresh rejected, or keychain entry missing | Sign in again (account stays listed, flagged) |
| Keychain unavailable | Explains how to unlock it; nothing is stored in plaintext as a fallback |

## Platform notes

- **Linux** needs a running Secret Service provider (GNOME Keyring or KWallet), unlocked.
- **Windows** Credential Manager limits a blob to 2,560 bytes. Tokens are stored as raw UTF-8 bytes
  (the string API would store UTF-16 and double the size). A real refresh token is ~1.5 KB.

## Testing

Everything except the real OS keychain is covered by unit tests against a mock server
(`cargo test`). The keychain test is ignored by default because most CI machines have no unlocked
keychain: run `cargo test -p kiln-core -- --ignored keyring` on a machine that has one.
It has been run on Linux with GNOME Keyring; macOS and Windows are untested.

## Rules the codebase already follows (keep them)

- All logic and tests live in `crates/kiln-core`; `src-tauri` only validates input, calls core and
  maps errors. Strict clippy: `unwrap_used`/`expect_used` are denied outside tests.
- Untrusted relative paths go through `paths::SafePath`/`validate_relative`. Never build file
  paths from archive entries, modpack manifests or IPC strings any other way.
- All network traffic goes through `net::HttpClient`: HTTPS only, per-client host allowlist, no
  redirect following, 2 MiB response cap, never logs URLs beyond host and path or any body.
  Redirect-following for downloads must re-check every hop against the allowlist.
- Secrets: refresh tokens only in the OS keychain; access tokens in `SecretString` (hidden from
  `Debug`, zeroized, auto-registered with the log redactor); no token crosses IPC or reaches a log.
  Never add a plaintext fallback.
- Every IPC command must be listed in `src-tauri/build.rs` `COMMANDS` **and** granted in
  `src-tauri/capabilities/default.json` (`allow-<kebab-name>`), and return `Result<T, AppError>`
  with a plain-English message. Validate inputs in the command (see `commands/auth.rs`).
- Strict CSP in `tauri.conf.json` (no inline scripts/styles, fonts self-hosted, `img-src` allows
  only Modrinth CDN and `textures.minecraft.net`). Avoid Svelte transitions (they inject `<style>`);
  use CSS transitions.
- Legal: no cracked/offline-auth features, no Minecraft logos or assets, state non-affiliation
  with Mojang/Microsoft, respect mod licences.
- No telemetry. No background polling when idle.
- Design language: "glaze" palette (celadon accent on slate-green dark; green-grey paper light),
  Bricolage Grotesque headings and Public Sans body, ruled rows instead of card grids, user-themeable
  accent. Follow the existing tokens in `ui/src/app.css`.

verify them against Mojang's form. The client ID is supplied by `KILN_MS_CLIENT_ID` (runtime, or at

## Your first steps

1. **If you received bundle files**: run `python3 restore.py` next to them (it writes `./kiln`,
   rejects any path that would escape that folder, fetches the GPL-3.0 `LICENSE` text if the
   network allows, and makes a baseline git commit). Then, because binary files can't travel in
   text bundles, regenerate the icons (the Rust build of `src-tauri` fails without them):
   `cd kiln/ui && npm ci && cd .. && pip install pillow && python3 tools/regen_icons.py`.
   Tauri's `src-tauri/permissions/autogenerated/*.toml` also regenerate on the first build; if
   `kiln-6-lockfiles.txt` was skipped, `Cargo.lock` and `ui/package-lock.json` are recreated by the
   first `cargo build` / `npm install` (commit them, and run the baseline to confirm nothing broke).
2. Install the toolchain if needed and run the baseline: `cargo test -p kiln-core` should report 76
   passed, 1 ignored, plus 1 logging integration test; then
   `cd ui && npm ci && npx svelte-check && npx vitest run`.
3. Start **Phase 3** immediately. Plan the module layout in a few lines (no new approval round),
   build it, and report as described above.

#!/usr/bin/env python3
"""Regenerate Kiln's app icons (original artwork, no Minecraft imagery).

Draws a 1024px kiln-mouth glyph with Pillow, then runs `tauri icon` (installed as a dev
dependency in ui/) to produce every size, and deletes the unused mobile icon sets.

    pip install pillow          # if missing
    (cd ui && npm ci)           # installs the Tauri CLI
    python3 tools/regen_icons.py [--out DIR]

`--out` defaults to src-tauri/icons. The Rust build of src-tauri needs these files to exist.
"""
import pathlib
import shutil
import subprocess
import sys

from PIL import Image, ImageDraw

ROOT = pathlib.Path(__file__).resolve().parent.parent


def draw(path: pathlib.Path) -> None:
    size = 1024
    img = Image.new("RGBA", (size, size), (0, 0, 0, 0))
    d = ImageDraw.Draw(img)
    d.rounded_rectangle((64, 64, size - 64, size - 64), radius=220, fill=(24, 33, 31, 255))
    d.rounded_rectangle((232, 300, 792, 800), radius=60, fill=(40, 54, 50, 255))
    d.pieslice((232, 250, 792, 610), 180, 360, fill=(40, 54, 50, 255))
    d.pieslice((372, 430, 652, 710), 180, 360, fill=(95, 185, 154, 255))
    d.rectangle((372, 570, 652, 800), fill=(95, 185, 154, 255))
    d.rectangle((372, 740, 652, 800), fill=(24, 33, 31, 255))
    img.save(path)


def main() -> int:
    out = ROOT / "src-tauri" / "icons"
    if "--out" in sys.argv:
        out = pathlib.Path(sys.argv[sys.argv.index("--out") + 1]).resolve()
    source = ROOT / "icon-source.png"
    draw(source)
    try:
        subprocess.run(
            ["npx", "tauri", "icon", str(source), "-o", str(out)],
            cwd=ROOT / "ui",
            check=True,
            stdout=subprocess.DEVNULL,
        )
    finally:
        source.unlink(missing_ok=True)
    for mobile in ("android", "ios"):
        shutil.rmtree(out / mobile, ignore_errors=True)
    print(f"icons written to {out}: {len(list(out.iterdir()))} files")
    return 0


if __name__ == "__main__":
    sys.exit(main())
